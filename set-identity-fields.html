Probes

Runs in sequence and takes about half a minute — the identity queue flushes every 2s, and three of the probes have to wait out that window to prove that nothing was sent.

idlefields reach the Identity Service
A call carrying fields puts them in the /identity body.
idlefields are normalized by name
The fields are sent sorted by name, whatever order the caller used.
idlereordering the same fields sends nothing
Same data in a different order must hash the same, so the identity is deduplicated.
idlechanging a field value sends a new identity
The resubmit case: lastName goes from empty to filled and must reach the service.
idlesetIdentity({fields}) is enough on its own
The shape integrations use: everything, the address included, goes in one array and no other argument is needed.
idlea legacy call carries no fields key
DXP signs users in with setIdentity({email, name}), so that call has to keep producing exactly the body it always did. This is backward compatibility, not a second option for an integration to choose.
