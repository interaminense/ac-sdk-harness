Cookie domain — hop between hosts

Two hosts that share a parent domain, one link between them. Host A establishes the anonymous ac_client_user_id; follow the link to host B and the id should be the same one — carried by the cookie, not by the link. That holds whether host B is new or already had an id of its own, because the shared cookie is what decides. How to read it

  1. On host A, hit Start over. The id is minted here and written to the cookie at the shared domain.
  2. Follow the link. Host B has its own storage and has never been visited, so it has no id of its own.
  3. Host B reports adopted and shows the same id. The link carries the expected value only so this page can compare the two — the SDK never reads it.
  4. Now hit Give this host an id of its own to stage the visitor who was already known here before the cookie existed. On the reload the id is replaced: the shared cookie decides, and the client reports the identity again under the id it settled on.

minted — nothing was there to take. adopted — this host had no id and took the shared one. replaced — it had one and gave way. kept — it already held that very id. An identified visit is the one case that keeps its own id, since it is stitched by its email hash downstream.
