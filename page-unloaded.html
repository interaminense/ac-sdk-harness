pageUnloaded and the unload deprecation

Chrome is retiring the unload event. The SDK used to report pageUnloaded (and its viewDuration) from an unload listener, so on any page load where Chrome enforces the deprecation the listener is refused and the event is never queued. LPD-100223 moves the reporting to pagehide. This page tells you which of the two the loaded SDK build is using, and exercises the back/forward cache cases that the move makes possible.

1. Which lifecycle event reports pageUnloaded?

Dispatches each event synthetically and watches for pageUnloaded. Synthetic dispatch is deliberate: it shows which listener the build registered, independent of whether this particular browser is currently enforcing the deprecation.

2. Real departure and back/forward cache restore

Navigates away for real and comes straight back with history.back(). Every event the SDK sends is mirrored to the harness log below before the queue is flushed, so the departure survives the navigation. A build that still listens for unload keeps the page out of the back/forward cache entirely, so the return is a full reload rather than a restore.

3. Tab events after a restore

The SDK disables tabBlurred / tabFocused on beforeunload so the visibility change caused by leaving is not reported. That flag lives on the module and was never reset, so once the move to pagehide lets a page reach the back/forward cache, a restored page would have had its tab events dead for good. Uses a real restore when probe 2 produced one; otherwise replays the same sequence synthetically.
