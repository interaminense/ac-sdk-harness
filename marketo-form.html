Marketo form

Drives the integration script from LPD-103259 against a stand-in for the liferay.com demo form — same Marketo form id, same field names, including the hidden campaign fields the real one carries. The script is loaded as a plain <script>, exactly as a site owner would. Navigation is intercepted rather than performed, so the page can report when it would have happened. Loads the SDK with ?sdk= and the script with ?script=; both accept local.

Probes

Each probe drives a fresh stand-in form through the script, the way a real submission would.

idlethe script exposes trackMarketoForm
Loading the file as a classic script is enough to reach it.
idleMarketo's own redirect is suppressed
The success handler returns false, which is what stops Marketo from navigating on its own.
idleonly the five mapped fields go out
The real form also submits Phone and a dozen hidden campaign fields; those must not reach the Identity Service.
idlethe email travels both ways
Hashed at the top level (the anchor the backend identifies by) and in plaintext inside fields (what fills the column).
idlenavigation waits for the request
The redirect must happen after the identity has left, not before.
idlea missing client does not break the form
With no Analytics on the page — an unaccepted consent banner — the visitor must still be redirected.
