flush()

Drives Analytics.flush() (LPD-103258) — the method that sends every queued message now instead of waiting for the flush loop, and resolves once the in-flight requests settle. This page runs with a 10 minute flush interval so the loop never fires on its own: every request you see below was caused by an explicit flush(). Probes

Takes about 10 seconds — one probe deliberately stalls the endpoint to watch the request timeout do its job.

idleflush sends what is queued
Nothing leaves on its own at this interval; the request appears only after flush().
idleflush resolves after the request, not before
The Promise must not settle until the send has actually completed.
idleflush resolves right away when nothing is queued
An empty queue must not cost the caller a round trip.
idlea second flush waits for the one in flight
Calling flush() during a flush must not hand back an already-resolved Promise.
idlea stalled endpoint settles on the request timeout
With the endpoint hanging, flush() still settles — via the existing REQUEST_TIMEOUT, around 5s. Isolates a single queue first, because the bound is per queue.

Sequential-queue ceiling

QueueFlushService processes its four queues sequentially, so the request timeout applies per queue rather than to the flush as a whole. With every queue stalled the ceiling is 4 × REQUEST_TIMEOUT, not one. This measures it — it takes up to 20 seconds on purpose.
